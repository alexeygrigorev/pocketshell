## 4. The findings worth carrying forward

These are the substantive lessons, not process trivia.

- **A guard built to eliminate vacuous test counts was itself vacuous.**
  #1741's fixture guard, whose whole purpose is to stop a dead runner reporting
  a green product verdict, had assertions that would pass while the nightly
  summary printed **`executed=0` beside `PASS`**. Cause: an unanchored `grep`
  asserts "this token exists somewhere in the file", not "this behaviour
  exists". Round 1 found 6 survivors in `connected-test.sh` (including a
  reportless runner borrowing the previous invocation's green XML); the reviewer
  then found 4 more in the nightly half, 3 silent. Both halves are now anchored
  to the constructs that own the behaviour.
- **A test named for a contract it did not constrain.** #1778's starter tests
  drove every drag observation with `isScrollInProgress = true`, so that guard
  alone carried them and the user-drag owner guard was never load-bearing —
  including in `activeUserAndProgrammaticOwnersBothBlockConcurrentCorrection`.
  Between touch-down and the first delta, Foundation publishes
  `DragInteraction.Start` while the pager still reports idle, which is exactly
  the window the reported defect lives in. The reviewer proved the replacement
  tests isolate the guard by showing **disjoint kill sets** between removing the
  owner guard and removing `isScrollInProgress`.
- **Measure before coding.** #1516's issue asked for a bounded socket read. The
  read was already unparked; the *caller* was unbounded
  (`withTimeoutOrNull` cannot return until its cancelled child finishes, and
  `exec`'s `finally` closes under `NonCancellable` through an 8s ceiling —
  2500 + 8000 ≈ the measured 10,512ms). The requested fix would have changed
  nothing.
- **`scripts/full-jvm-gate.sh` was a Python program despite the `.sh` extension.**
  Running it under `bash` mis-executes it; line 3's `import os` invokes
  ImageMagick's `import`, which blocks forever on X **while holding the shared
  gate lock**, starving every sibling lane, with a ~1-line log and zero XML.
  Documented in `process.md`; it burned a lane this session and is the most
  likely explanation for the 2026-07-27 #1598 gate that "stalled" with no
  verdict. (Historic path. #2066 renamed it to `scripts/full-jvm-gate.py`,
  along with two sibling instances the by-name documentation had hidden, and
  added `scripts/check-script-interpreter-hygiene.sh` so the class cannot
  return.)
- **Cross-agent damage extends to shared FILES, not just processes.** A sibling
  overwrote another lane's `mutate.py` in the shared scratchpad, so one mutation
  run executed **unmutated production code** and reported green — which argues
  for exactly the wrong conclusion, since an unmutated green is
  indistinguishable from adequate tests. Another sibling's
  `connected-test.sh --include-base` sweep repeatedly wiped a lane's journey
  artifacts. Both now documented in `process.md`.

## 7. Standing reminders

- The root checkout stays on synced `main` and never switches branches.
- `git diff` omits untracked files. Four candidates this session had load-bearing
  untracked files — new production classes, new tests, new guard scripts. Always
  `git -C <wt> ls-files --others --exclude-standard` and copy them, verifying file
  modes.
- Do not infer green from a systemd unit's `Result=success`; a `Type=oneshot`
  unit populates that field **while still running**.
- Merging to `main` cancels an in-flight `main` batch run via the concurrency
  group. That is sanctioned batching, but check what the in-flight run is
  validating before triggering it.
