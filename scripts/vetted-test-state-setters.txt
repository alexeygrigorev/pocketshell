# Vetted connected-test STATE-INJECTION seams (issue #1430, child of #848).
#
# WHY THIS FILE EXISTS
# --------------------
# A connected / journey test (app/src/androidTest, shared/*/src/androidTest) can
# be GREEN while the real production path is BROKEN when its load-bearing
# assertion is driven from a `*ForTest` STATE-INJECTION seam that injects a state
# production can NEVER reach on its own. The #1158 `forceActivePaneAltBufferForTest`
# cheat (now deleted) did exactly that — it forced an alt-buffer flag the real
# tmux -CC seed path never sets — and hid a 5x-recurring Conversation-tab bug for
# weeks. `scripts/check-test-validity.sh` could not grep for it because the
# discriminator is SEMANTIC: *can the real path produce this state at all?*
#
# This registry is the answer the audit (#848 comment 4929654015, option (b))
# recommended: an EXPLICIT allowlist of the state-injection seams whose injected
# state the real path GENUINELY reaches (the #780 model — the injection only makes
# a real-but-nondeterministic on-device state deterministic on the fast x86 AVD).
# The SEAM1 detector in check-test-validity.sh HARD-FAILS a connected test that
# calls or assigns a production-defined state-injection seam (force*ForTest /
# *Override*ForTest / set*ActiveForTest) that is NOT listed here and has no
# inline `// SEAM_JUSTIFIED:` opt-out. That forces the reviewer to write down,
# for every NEW synthetic connected proof, WHY the real path reaches the
# injected state — the exact judgement that was skipped for alt-buffer.
#
# FORMAT (enforced): one entry per line
#     <seamName>  # <one-line real-path-reachability justification>
# The justification after `#` is REQUIRED — a bare seam name with no reason is a
# hard error (registry additions must be deliberate and vetted). Lines that are
# blank or start with `#` are ignored (this header).
#
# SCOPE NOTE: the SEAM1 detector only consults the state-INJECTION shape
# (force*ForTest / *Override*ForTest / set*ActiveForTest) — the narrow, highest-
# signal shape the alt-buffer cheat took. Plain config/dispatcher/timeout knob
# setters (setExecDispatcherForTest, setSendTimeoutForTest, ...),
# exact-production-call wrappers (clearAgentDetectionForPaneForTest,
# applyRecordedShellVerdictForTest), lifecycle gates (setProcessStartedForTest),
# user-setting pins (setDefaultAgentSessionViewForTest) and read-only accessors
# are NOT injection-shape and are not gated by SEAM1, so they do not need an entry
# here (the #848 audit cleared them as legitimate #780-model seams).

forceTreeStaleForTest  # FolderListViewModel: wraps the EXACT production call tree.markReconcileDueForTest(); the real path marks the tree due for reconcile on its real timer/change, so this only makes that reachable transition deterministic.
forceControllerAttachingForTest  # TmuxSessionViewModel: submits the exact ConnectionController Switch event, reaching typed Attaching exactly as runFastSessionSwitch/fastSwitchSessionForTest does before the target-tagged reveal; it does not assign state directly.
setRenderDrainBackloggedOverrideForTest  # TerminalSurfaceState: the seam's own doc confirms the maintainer's on-device freeze DOES drive the drain-backlogged state under a heavy Codex burst + IME amplifier; only the fast CI/dev x86 AVD never backlogs, so the override makes that real on-device state deterministic (textbook #780).
forceControllerReconnectingStatusKeepingClientForTest  # TmuxSessionViewModel: submits the exact ConnectionController remote-drop event while retaining the independently writable clientRef; a real liveness-probe/drop edge reaches the same typed Reattaching state, and Issue1686QueueDrainWireOracleDockerTest keeps the real SSH `-CC` fixture wire alive to prove send admission follows that wire rather than the lifecycle label.
forceTransportProvenAliveForTest  # BOTH production owners are vetted: TmuxSessionViewModel and ForwardingController pin the same live SshSession keepalive oracle; real traffic makes it true inside the keepalive window, while no/aged-out/dead transport makes it false, so assignments only make both real liveness verdicts deterministic without inventing a third state.
forceLivenessProbeDeadForTest  # TmuxSessionViewModel: makes the bounded tmux control-channel probe return dead; a real half-open/dead channel reaches the same false probe result, while the assignment removes the wall-clock/network nondeterminism needed to reproduce that state on the healthy agents fixture.
forceRestoreReaderActivityStaleForTest  # TmuxSessionViewModel: makes the #1533 reader-activity vouch stale; a real quiet/dead control channel reaches the same verdict after its activity window expires, while the seam deterministically exposes the authoritative keepalive/probe restore branches on the busy healthy fixture.
forceCleanOutageForTest  # TmuxSessionViewModel: makes passive-reattach and fresh-transport attempts fail during a bounded recoverable outage; real clean EOF followed by FIN/connection-refused reaches those same failures, and clearing the assignment models the real link returning before the reconnect ladder expires.
forceUnrecoverableHostForTest  # TmuxSessionViewModel: makes every reconnect-triggered reattach/fresh dial fail until the bounded ladder exhausts; a dead sshd, blackholed port, or network cut lasting past the ladder reaches that same Unreachable path, while cold initial attach remains real.
forceNextReseedApplyParkedForTest  # ReseedApplyRaceTestGate (#2178): holds a `capture-pane` reseed between its round-trip and its apply. The real path is IN that state on every attach — the device log records the reveal->reseed window at 245-460ms on every run — so this only makes a genuinely-reached, genuinely-typeable window deterministic instead of a coin flip (textbook #780). It injects no state the reseed does not already pass through: the same code runs, at the same point, with the same snapshot.
forceReleaseOfParkedReseedAppliesForTest  # ReseedApplyRaceTestGate (#2178): releases the applies parked by the seam above while keeping later ones held. The release is what production does unconditionally (the apply proceeds); keeping the seam armed freezes the LATER painters so the journey can observe whether the released apply destroyed the typed bytes — without it the #966 stale-render heal re-fetches them from the shell's line editor and the proof passes on a fully defective build (measured 1 run in 3).
dispatcherOverrideForTest  # ComposerDraftPersistence: selects only the coroutine dispatcher for the exact production SharedPrefs save/clear/identity-promotion bodies; production Dispatchers.IO provides an independent runnable pool while #1602 deliberately blocks one queue worker, and the journey snapshots then restores the prior override in close()/terminal cleanup, so no synthetic draft state or test dispatcher leaks.
